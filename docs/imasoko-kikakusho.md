# いまそこ

**キャッチコピー:集合、リンク一本で。**

URLを共有するだけで、参加者全員の現在地をリアルタイムにキャンパスマップ上へ表示する、集合支援Webアプリ。ログイン不要・アプリインストール不要。

---

## 1. 課題

大学構内で友達と集合する際、「今どこ?」「何号館の何階?」というやり取りが毎回発生する。特に新入生や広いキャンパスでは、建物名だけでは位置が伝わりにくく、結局待ち合わせに時間がかかる。

この課題を分解すると、次の3つの問題が重なっている。

1. **言葉で位置を伝えるコストが高い**
   「◯号館の前」と言われても、キャンパスに不慣れな新入生にはどの建物か分からない。建物の正式名称・通称・番号が混在し、共通の語彙が成立していないことも多い。

2. **やり取りが往復する**
   「今どこ?」→「◯号館」→「どこの入口?」→「北側」→「着いたけどいない」…と、テキストのやり取りが何往復も発生する。位置は刻々と変わるため、テキストでのやり取りは常に情報が古くなる。

3. **既存の位置共有手段は導入コストが高い**
   汎用の地図アプリの位置共有機能は、アカウントログインや相手との連絡先交換が前提になっているものが多く、「今日初めて会うサークルの新入生同士」のような希薄な関係では使いにくい。専用アプリのインストールを全員に求めるのも、一度きりの集合のためには重い。

## 2. コンセプト

**「URLを開くだけ」で完結する、使い捨ての位置共有ルーム。**

- **ログイン不要** — アカウント登録・連絡先交換なしで、その場のグループだけで使える
- **インストール不要** — ブラウザで開くだけ。iPhone/Androidを問わない
- **リンク一本** — LINEグループやDiscordにURLを1つ貼れば、全員が参加できる

既存の位置共有サービスとの違いは「関係の軽さ」に最適化している点にある。恒常的な位置共有ではなく、「今日のこの集合のためだけ」に使い、集合が終われば消える一時的なルームとして設計する。

## 3. ユーザーフロー

### 部屋を作る人(ホスト)

1. トップページで「ルームを作る」ボタンを押す
2. 共有用URLが即座に発行される
3. URLをLINEグループ等に貼って共有する
4. 自分も名前を入力し、位置情報の利用を許可して参加する

### 参加する人

1. 共有されたURLをタップして開く
2. 表示する名前(ニックネーム可)を入力する
3. ブラウザの位置情報許可ダイアログで「許可」を押す
4. 参加完了 — マップ上に自分と全員のピンが表示される

参加までの所要時間は数十秒を想定。フォーム入力は名前1項目のみ。

## 4. 機能詳細

### 4.1 部屋作成

- ワンタップでルームを作成し、共有用URLを発行する
- URLには推測困難なランダムなルームIDを含め、URLを知っている人だけが参加できるようにする(案)
- URLのコピー・共有ボタンを用意し、LINE等への貼り付けを1タップで行えるようにする(案)
- **ルームは private / public を切替可能(既定 private)**。private はURLを知る人だけ、public は一覧公開(詳細:[05](./05_feature-design.md))

### 4.2 参加

- URLを開くと名前入力画面が表示される
- 名前を入力し、位置情報を許可するだけで参加完了
- 屋内にいる場合は、自分の階数を手動で選択できる(いつでも変更可)。GPSでは階数を取得できないため、階数は自己申告方式とする
- 位置情報を拒否した場合でも、他の参加者の位置を「見るだけ」で参加できるようにする(案:はぐれた側だけが位置を出したいケースへの対応)

### 4.3 リアルタイム地図表示

- 参加者全員のピンが、名前付きでキャンパスマップ上に表示される。階数を選択している参加者は、名前の横に階数が表示される(例:「たくま 3F」)
- 各参加者の移動に追従して、ピンの位置がリアルタイムに更新される
- 自分のピンと他人のピンは色や形で区別する(案)
- 「自分の位置に地図を戻す」「全員が収まる縮尺にする」ボタンを用意する(案)
- **マップは3エリア(駅×2 + 有明キャンパス)を切替表示**。キャンパスでは**建物を選ぶと階・各階の教室を視覚表示**(詳細:[05](./05_feature-design.md))

### 4.4 集合場所の指定

- 参加者の誰かがマップ上をタップして集合地点をピン留めできる
- 集合地点は全員の画面に即座に共有される
- 集合地点ピンは参加者ピンと明確に区別できる見た目にする(案)
- 各参加者から集合地点までのおおよその距離を表示する(案)
- 集合地点は **タップした座標 / 特定メンバーの現在地 / 場所(教室・「1号館前」等)** から指定できる
- 参加者は**空いている教室などの候補を追加**でき、そこから集合地点を選べる(空き教室データは当面手入力。詳細:[05](./05_feature-design.md))

### 4.5 ルームの有効期限

- ルームは作成から一定時間で自動的に無効化され、以降は位置の共有・閲覧ができなくなる
- 「今日のこの集合のためだけ」の使い捨てルームであることを、プライバシー面の設計として保証する
- 具体的な有効時間(例:数時間)は要決定

## 5. 技術構成

```
┌──────────────────────┐            ┌─────────────────────────┐
│  ブラウザ              │            │  個人サーバー(自前ホスト)  │
│                      │   HTTPS/   │                         │
│ React + TypeScript   │  WebSocket │ リバースプロキシ           │
│  ├ Leaflet(地図)    ─┼───────────▶│  └▶ FastAPI (Python)    │
│  └ Geolocation API   │            │      ├ ルーム管理         │
│                      │◀───────────┼─     │ (インメモリ)      │
│                      │  全員の位置  │      ├ 有効期限管理      │
│                      │  を配信     │      └ 静的ファイル配信   │
└──────────────────────┘            └─────────────────────────┘
```

- **フロントエンド**:React + TypeScript(Vite)。地図描画は Leaflet を使用し、ブラウザ標準の Geolocation API(`watchPosition`)で現在地を継続取得する
- **キャンパスマップ**:実際の地理に忠実な配置・縮尺で描いた自作マップ画像を、Leaflet の `imageOverlay`(`CRS.Simple`)で表示する。建物名・号館番号は学内の通称で地図に直接描き込む。Geolocation API が返す緯度経度は、基準2点によるキャリブレーションと線形変換でマップ座標に変換してピンを配置する
- **バックエンド**:FastAPI(Python)。WebSocket でブラウザと常時接続し、ルームIDごとに参加者と最新位置をインメモリで保持、同じルームの参加者全員へ位置更新を配信する。ルームの有効期限管理(自動無効化)もサーバー側で行う。データベースは使用しない
- **配信**:React のビルド成果物を FastAPI の静的ファイル配信で提供し、フロントとAPIを同一オリジンにまとめる(CORS設定不要)
- **デプロイ**:チームメンバーが運用する個人サーバー上でホストする。Geolocation API の制約上 HTTPS が必須のため、リバースプロキシで TLS 終端と WebSocket の中継を行う
- **配布形態**:Webアプリのみ。ネイティブアプリは作らない

位置情報の取得には HTTPS が必須(Geolocation API の制約)であるため、デモ環境も HTTPS で用意する。

## 6. ターゲット

- **大学の新入生** — キャンパスの地理に不慣れで、待ち合わせに苦労しやすい層。連絡先を交換したばかりの相手との集合が多く、「ログイン不要・関係が軽い」設計が最も刺さる
- **サークル・ゼミ・友人グループ** — 日常的に学内で集合する学生。毎回の「今どこ?」のやり取りを削減する

## 7. 利用シーン

- サークルやゼミの集合前
- 新入生同士の初めての待ち合わせ
- 学食や空き教室での急な合流
- オリエンテーション・キャンパスツアーでのはぐれ防止

## 8. 決定事項と残る検討点

### 決定事項

- **階数の扱い**:参加者が自分の階数を手動で選択・表示する(4.2 / 4.3 参照)
- **ルームの寿命**:ルーム作成から**既定2時間**で自動無効化(設定可, 4.5 参照)
- **キャンパスマップ**:実際の地理に忠実な**自作SVG**を Leaflet で表示。対象は**有明キャンパス**、作画は**ホスト**担当。**3エリア切替**(駅×2 + キャンパス)
- **ルーム公開範囲**:private / public を切替可能、**既定 private**(4.1)
- **集合場所**:座標 / メンバー / 場所(教室・「1号館前」等)の3タイプ + 空き教室のユーザー追加(4.4)
- **途中退出**:可能(明示退出をサポート)
- **位置履歴**:サーバーは最新位置のみ保持し、履歴を残さない

追加機能の詳細設計は [開発ドキュメント docs/05](./05_feature-design.md) に集約。

### 残る検討点

- `position` 送信のスロットリング間隔(実機で確定)
- 空き教室データの公式ソースへの切替(規約クリア後。当面は手入力CSV)
